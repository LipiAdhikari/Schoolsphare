# SchoolSphere — Premium SaaS Public Website UI Design Master Prompt

Act as a world-class SaaS product designer, senior UI/UX architect, visual design director, and frontend design specialist.

Design a complete, high-fidelity public marketing website for **SchoolSphere**, a modern multi-school School Management System built for schools in Nepal.

The goal is to create a premium, professional, visually impressive, conversion-focused SaaS landing page that feels like a real funded software product, not a generic school website template.

**Deliverable:** A complete website UI design covering the full page from navigation to footer, with realistic interface previews, detailed section layouts, reusable visual patterns, and responsive desktop/mobile behavior.

If using a visual design generator, prioritize the rendered website composition. If using a coding agent, implement the actual responsive frontend in the existing Laravel + Inertia.js + React + TypeScript + Tailwind CSS project.

## 1. Brand identity

**Brand name:** SchoolSphere  
**Product:** Smart School Management System  
**Market:** Nepal  
**Audience:** School owners, principals, administrators, teachers, students, and parents.

Brand personality:

- Premium.
- Trustworthy.
- Modern.
- Intelligent.
- Minimal.
- Efficient.
- Approachable.
- Academically professional.

The design should communicate that SchoolSphere helps schools manage their daily operations from one connected platform.

### Visual inspiration

Use the visual quality and restraint of contemporary SaaS websites such as Linear, Stripe, Notion, and Vercel as general inspiration. Do not copy their layouts, branding, or distinctive visual assets.

Prioritize excellent typography, confident whitespace, precise alignment, clean product mockups, and a coherent design system.

## 2. Visual design system

### Color palette

Use a sophisticated, predominantly white interface.

- Primary navy: `#17233B`
- Primary blue: `#3563E9`
- Blue hover: `#244DC7`
- Main background: `#FFFFFF`
- Alternate section background: `#F6F8FC`
- Soft blue surface: `#EEF3FF`
- Main text: `#1A2438`
- Secondary text: `#68748A`
- Borders: `#E5EAF2`
- Success: `#16845B`
- Warning: `#C58A25`

Use blue as a controlled accent for CTAs, links, active navigation, selected controls, and important product details.

Do not flood the page with blue backgrounds. White should remain the dominant surface.

Avoid purple gradients, excessive saturated colors, glassmorphism, neon effects, and heavy shadows.

### Typography

Use Inter or a comparable premium sans-serif typeface.

- Large, bold, tightly composed hero headline.
- Clear section headings.
- Comfortable paragraph widths.
- Consistent font weights.
- Restrained letter spacing.
- Readable labels inside dashboard mockups.

The visual hierarchy must be obvious even when the page is viewed at a glance.

### Layout

- Desktop design reference: 1440px wide.
- Centered content container: approximately 1180–1240px.
- Generous horizontal spacing.
- Large vertical separation between major sections.
- Consistent 8px-based spacing rhythm.
- Subtle 1px borders.
- Modest 10–16px corner radii for UI surfaces.
- Strong alignment between section headings and content.
- Minimal, realistic shadows.

The page should feel spacious but not empty.

## 15. Responsive design

Create desktop, tablet, and mobile versions.

### Desktop

- Full navigation.
- Two-column hero.
- Large dashboard preview.
- Multi-column feature grid.
- Detailed product mockups.
- Horizontal workflow.

### Tablet

- Tighter container widths.
- Reduced headline sizes.
- Adaptable dashboard preview.
- Two-column feature layout where appropriate.
- Simplified navigation.

### Mobile

- Compact navigation and accessible menu.
- Single-column hero.
- Headline with natural wrapping.
- Full-width CTA buttons where useful.
- Dashboard preview scaled or cropped intelligently.
- Single-column feature cards.
- Stacked role previews.
- Vertical workflow.
- Accordion FAQ.
- Stacked footer groups.

Do not merely shrink the desktop page. Recompose each section to preserve readability and hierarchy.

## 16. Motion and interaction design

Use restrained, purposeful interactions:

- Smooth anchor scrolling.
- Subtle button hover states.
- Small card elevation on hover.
- Dropdown transitions.
- Working feature-preview tabs.
- Accessible FAQ accordions.
- Responsive mobile navigation.
- Gentle reveal transitions only where they improve comprehension.

Respect `prefers-reduced-motion`.

Do not use continuous floating animations, excessive parallax, distracting cursor effects, or animation that delays access to content.

The page must remain attractive and usable with animations disabled.

## 17. Visual quality requirements

The final design must:

- Look intentionally art-directed.
- Use a consistent design system.
- Maintain strong typography and alignment.
- Have realistic product UI previews.
- Use believable, clearly illustrative sample data.
- Avoid generic stock-photo dependence.
- Avoid arbitrary floating cards.
- Avoid excessive gradients.
- Avoid inconsistent icon styles.
- Avoid excessive empty space that makes the page feel unfinished.
- Avoid overly dense content.
- Avoid fake customer logos, testimonials, certifications, or performance statistics.

The dashboard preview is a major part of the brand presentation. Make it detailed, polished, and visually convincing.

## 18. Implementation instructions for coding agents

If generating code:

- Inspect the existing Laravel repository first.
- Follow the installed Inertia.js and React conventions.
- Use TypeScript.
- Use Tailwind CSS and reusable components.
- Build the public website using a shared marketing layout.
- Create reusable dashboard-preview components.
- Keep public marketing routes separate from authenticated portal routes.
- Use working navigation and actual interactive state.
- Ensure the UI compiles.
- Run the available production build.
- Avoid fake backend integrations.
- Do not change the multi-tenant architecture to simplify the UI.
- Do not expose school data or protected page props publicly.

Create the homepage first, validate its design and responsive behavior, then implement the feature, solution, FAQ, and legal pages using the same design system.

Create a polished, high-fidelity SchoolSphere public website that could credibly represent a premium Nepal-focused SaaS product.
